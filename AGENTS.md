# CacheTrim: памятка для разработчика и ИИ

## Назначение и безопасность

CacheTrim — настольное приложение Windows для очистки и настройки ПК, которым пользуются и друзья владельца. Приложение запрашивает права администратора; ошибочное удаление или системная настройка может навредить. Не обещай прирост FPS. Не отключай службы, антивирус, защиту, не удаляй файлы пользователей и не меняй параметры без понятного подтверждения и возможности корректного отката. Тесты удаления запускай только в созданных для них временных каталогах. Не публикуй неподтверждённую сборку как работающую.

## Что где

- `wpf/CacheTrim.Wpf.csproj` — актуальная основная программа, WPF на .NET 10, Windows x64. `MainWindow.xaml.cs`, `MainWindow.Pages.cs` и другие `MainWindow.*.cs` — частичные классы интерфейса; `App.xaml.cs` — запуск, включая режим `--silent`.
- `winui/Core/` — актуальная логика, подключаемая в WPF-проект: очистка, конфигурация, Windows API, автозагрузка, планировщик, обновление и запуск команд. `winui/TweakCatalog.cs` — каталог системных настроек. Старые исходники в `src/` не являются точкой входа текущей WPF-сборки.
- `companion/DesktopPet/` — Клод: отдельное прозрачное окно поверх рабочего стола, а не виджет внутри CacheTrim. Картинки лежат в `Assets/`. Кнопка во вкладке «Питомец» проверяет и запускает отдельный `DesktopPet.exe` из GitHub Release.
- `winui/Core/CleanupOptions.cs` — исключения, выбор браузеров и минимальный возраст файлов; повреждённые настройки останавливают очистку. `CleanupPresets.cs` сохраняет только флаги категорий. `FileReview.cs` только ищет крупные файлы, дубликаты, установщики и записи, ничего не удаляет.
- `winui/Core/GameGuard.cs` — приблизительная защита от запуска обслуживания во время игры; процесс игры добавляется по EXE, полноэкранный режим определяется Windows. `TaskSetup.cs` содержит отдельное необязательное ежедневное расписание, ограниченное простоем и питанием от сети.
- Выбор компаньона на вкладке «Питомец» предлагает Клода и отдельно предоставленный пользователем AnimeAvatar.exe. По прямой просьбе владельца его неизменённые части встраиваются в приложение как ресурсы и восстанавливаются при первом запуске; код сборки и проверки — `winui/Core/AnimeAvatarPackage.cs`. Исходников и цифровой подписи аватара нет. Закреплённый SHA-256 подтверждает только совпадение с присланным файлом, не безопасность; перед запуском показывается предупреждение о возможных правах администратора. Уведомления компонентов доступны во вкладке питомца. Не внедряй функции Клода в этот EXE. Реальный запуск аватара ещё требует проверки.
- В меню Клода «Принеси секрет» показывает случайную вещь и сохраняет её в коллекцию; текст песни временно приостанавливается, чтобы не перекрыть сообщение. «Почему нет текста песни?» показывает состояние поиска.
- Клод V2 — отдельная модель, оригинал сохранён. Локальные команды и Vosk — `VoiceCommandCatalog.cs` / `VoiceCommandSession.cs`; облачный незавершённый помощник — `CloudAssistant.cs`, `MainWindow.CloudAssistant.cs`, `CloudSpeech.cs`, `CloudVoiceRecorder.cs`. Groq-ключ защищается Windows DPAPI и хранится только у пользователя, не в GitHub. Клиент не может проверить тариф, поэтому нужно использовать именно бесплатный; платный ключ может привести к расходам. До 15 секунд голосовой задачи хранится в памяти и отправляется в Groq; при включённом пользователем вызове «Джарвис» локальный распознаватель постоянно слушает микрофон. `ScreenCapture.cs` и `ScreenVision.cs` по отдельной кнопке снимают основной экран в память и отправляют вместе с вопросом в Groq (qwen/qwen3.8-27b): на снимке могут быть личные данные; это только просмотр без управления. Индикатор показан на питомце; отмена запроса общая. Смена модели/закрытие отменяет работу. Облачные действия жёстко разрешены по именам и схемам аргументов; произвольный shell, URL и пути, заданные моделью, запрещены. `PresentationBuilder.cs` создаёт простой текстовый PPTX на базе `Assets/presentation_template.b64` в Documents/CacheTrim/Презентации, без перезаписи и без проверки фактов; шаблон генерируется `tools/build-pet-presentation-template.mjs` в среде с Notion pptx skill. Запуск Telegram проверяет стандартные пути и передаёт программу Explorer; запуск на реальном Windows не проверен. Текстовый режим ИИ открывает главную YouTube или поиск, но не выбирает видео. `tests/CloudAssistantTests` использует заглушки сети. Реальные API, снимок экрана и микрофон проверить вручную, не выдавать первый этап за полноценного Джарвиса. Питомец, запущенный из CacheTrim, наследует права администратора: до добавления управления вводом нужен надёжный запуск без повышенных прав, защита от инструкций на экране, аварийная остановка и испытания на Windows.
- `companion/DesktopPet/LyricsService.cs` и `LyricsTimeline.cs` — необязательные метаданные медиасеанса и поиск синхронных строк через LRCLIB; по умолчанию выключено, включение требует согласия пользователя. Аудио не отправляется и не транскрибируется. При нескольких проигрывающих приложениях приоритет у Spotify для Windows; Spotify в браузере определяется как браузер. После сетевого поиска повторно проверяется текущий трек; пустая строка или пауза скрывает только текст песни, не обычную реплику. Ответы Retry-After учитываются между сменами треков.
- `winui/Core/NetworkDiagnostics.cs` — только по запросу пользователя DNS и четыре ICMP-проверки выбранного адреса, без сброса и изменения сети. `DisplayDiagnostics.cs` читает текущий режим и варианты частот по данным Windows, не меняя настройки.
- `tests/` — тесты и Windows smoke-проверки. `.github/workflows/` — сборка, проверки и публикация. `RELEASE_NOTES.md` — описание текущего выпуска; `wpf/ReleaseHistory.cs` запрашивает публичные стабильные релизы GitHub для окна после обновления и отдельной вкладки «Что нового» (`wpf/MainWindow.ReleaseHistory.cs`). Во вкладке при ошибке сети отображаются встроенные заметки установленной версии с предупреждением; частичная история помечается.
- `docs/` — изображения документации; `tools/` — вспомогательные инструменты. `dist/`, `bin/`, `obj/` — результаты сборки, не источник истины.

## Проверка и выпуск

1. Проверь текущие `main`, открытые ветки и последнюю версию релиза перед изменениями.
2. Собирай WPF и Desktop Pet под Windows, запускай `tests/WhatsNewTests`, `tests/CleanerSafetyTests`, `tests/FileReviewTests`, `tests/TaskSetupTests`, `tests/CleanupPresetsTests`, `tests/NetworkDiagnosticsTests`, `tests/DisplayDiagnosticsTests`, `tests/LyricsTests`, `tests/PetUiTests`, `tests/UpdateSafetyTests` и Windows smoke-проверки. Проверки GitHub Actions не заменяют визуального тестирования и тестов на реальных устройствах.
3. Версии в `wpf/CacheTrim.Wpf.csproj` и `winui/Core/AppInfo.cs` должны совпадать. В выпуске нужны `CacheTrim.exe`, `DesktopPet.exe` и отдельные файлы SHA-256. Не перезаписывай ранее опубликованные EXE и контрольные суммы: ими пользуется обновлятор друзей.
4. Сохраняй описание изменений и указывай ограничения. Если история GitHub недоступна, приложение показывает заметки текущего релиза с предупреждением. Старые релизы могут не иметь подробных заметок.
5. После работы обновляй эту памятку, не записывай в неё токены, пароли или приватные данные.

## Известные ограничения на момент создания этой памятки

- Жидкое стекло использует Desktop Acrylic на поддерживаемой Windows 11, иначе сплошной фон. Внешний вид на разных устройствах ещё не проверен вручную.
- В меню Клода есть непрозрачность, стартовая позиция, периодические напоминания, показ рабочего стола и открытие загрузок. Напоминания работают только пока питомец запущен и не перебивают режим «Не отвлекать». Автозапуск по выбору пользователя создаёт отдельную запись HKCU Run и запускает EXE напрямую без проверки CacheTrim, от текущего пользователя; чужую изменённую запись не трогает. В CacheTrim есть поиск по разделам и выбираемые глобальные сочетания Ctrl+Alt+F7–F12, работающие только пока CacheTrim открыт; Windows может отказать, если сочетание занято.
- Клод может запускаться без сети: `PetCache` сверяет файл с SHA-256, встроенным в CacheTrim, и держит файловый дескриптор открытым до запуска. При первой загрузке нужен GitHub Release той же версии. Для верифицированных питомцев v2.1.15, v2.1.16 и v2.1.17 предусмотрен запасной вариант с явным согласием; контрольная сумма встроена отдельно. Не запускай непроверенную копию, особенно при правах администратора. Сборка релиза сначала собирает питомца и передаёт его SHA-256 через `TrustedDesktopPetSha256` в WPF; нельзя использовать в готовом релизе значение по умолчанию от старой версии. Индикатор долгой операции — неопределённый прогресс; при скачивании обновления процент выводится только при известном размере, а затем отдельно показывается проверка.
- У отката игрового профиля без сохранённой копии могут использоваться стандартные значения вместо прежних пользовательских. Не называй такой откат точным.
- Питомец не распознаёт речь из системного аудио. Текст песни, если поддерживается в текущей ветке, получается из метаданных совместимого медиаплеера и внешнего сервиса только после согласия пользователя; звук не отправляется. Наличие и синхронизация текстов зависят от плеера и сервиса.
- Защита игр не распознаёт все игры; уже запущенные системные утилиты не прерываются. Проверка файлов при очистке выполняется периодически, а не непрерывно. Расписание запускается только при включённом сеансе пользователя и по текущим сохранённым настройкам; Windows может запустить пропущенную задачу позже.
- Фактический запуск задачи планировщика, текст песен с реальным проигрывателем, аниме-аватар, внешний вид и работа аудио на настоящем ПК нуждаются в ручной проверке.
- Экспериментальные изменения из ветки не являются релизом до прохождения всех проверок и публикации. Уточняй фактический статус по GitHub, не по названию файла.

- У аниме-аватара отдельная горячая клавиша с тем же предупреждением, что при обычном запуске. Меню Клода сгруппировано в раскрываемые разделы; элементы и обработчики нужно сохранять.

- `WindowChrome.GlassFrameThickness` должен быть полным для Desktop Acrylic, иначе он может отменить DWM-рамку; при выключении темы рамку надо вернуть в ноль. Успех DWM не доказывает, что пользователь видит размытие: Windows может показать сплошной фон. Нужна визуальная проверка на реальном ПК.
- Перезапуск компаньона ищет запущенный EXE по точному пути в CacheTrim/Companion, посылает WM_CLOSE и не завершает другие процессы принудительно. Аниме-аватар остаётся неподписанным и требует подтверждения.

- Перед запуском аниме-аватара удерживай открытый дескриптор проверенного файла до запуска, как у Клода. Повторный запуск определяется по полному пути EXE, а не только по имени процесса. Явный запрос секрета имеет приоритет над текущим напоминанием.

- Тестовая модель Клода хранится отдельно в `companion/DesktopPet/Assets/claude_experimental.b64` (PNG, сгенерирован по оригиналу и подготовлен с прозрачным фоном). В меню доступны обычная и тестовая модели; у тестовой пока одна поза. Старая модель и её четыре позы сохраняются. Не запускай тестовую модель из старого проверенного файла питомца: в нём её нет.

- Клод V2: необязательный контекст хранит только четыре последних пары сообщений в памяти и отправляет их в Groq при последующих запросах; он выключен по умолчанию и очищается по кнопке, при выключении и смене модели. Режим экрана отдельно и не входит в контекст. Поиск YouTube использует только фиксированный HTTPS-хост, проверенную строку запроса и URL-кодирование; он не запускает видео.
- `build.ps1` собирает питомца и приложение как согласованную пару, закрепляет и проверяет SHA-256; локальный `DesktopPet.exe` рядом с основным EXE устанавливается только после проверки хеша. Старые релизные хеши не допускаются для модели V2. Это экспериментальная локальная сборка, не новый релиз.
- Неполные сохранённые настройки очистки останавливают её; `--silent` требует сохранённый `config.ini`. Новая задача входа не имеет 10-минутного лимита; ранее созданную задачу пользователь должен отключить и включить заново.

- Эксперимент управления ПК: `ComputerAgent.cs`, `ComputerInput.cs`, `ComputerControlPanel.cs`, `MainWindow.ComputerControl.cs`. Только основной экран; опциональный авторежим с предпросмотром и паузой или ручное подтверждение каждого шага; ограничение 20 шагов; повторный снимок и приблизительная проверка области щелчка; работа запрещена при повышенных правах процесса. Это НЕ полностью автономный режим и не проверен на Windows и реальном API. Из-за наследования прав от CacheTrim запускайте DesktopPet напрямую без администратора.

- Управление ПК можно начать голосовой командой до 15 секунд; запись отправляется в Groq, текст показывается для подтверждения. Модель может запросить фиксированное открытие YouTube, запуск установленного Telegram Desktop и уровень системной громкости 0–100%; режим определяет необходимость подтверждения. Громкость — default multimedia output master, состояние mute не меняется. Автономная работа и практическая работоспособность на Windows/реальном API не подтверждены.

- Обновление авторежима управления: после подтверждения задачи шаги могут выполняться автоматически с трёхсекундной паузой и кнопкой остановки. При выключенном авторежиме каждый шаг требует подтверждения; некоторые очевидно рискованные действия запрашивают его и в авторежиме. `ComputerSafety` проверяет лишь текст и отдельные клавиши, не защищает от всех опасных или внедрённых действий. Нельзя обещать безопасность или автономную работу: на Windows и с реальным API они не проверены. Запуск с правами администратора заблокирован.

- Экстренное голосовое «стоп»: `EmergencyStopSession` и `EmergencyStopPhrase`, локальный Vosk, только во время активной задачи (после записи исходной голосовой команды). Кнопка остановки остаётся; слушание отображается, запрос голосовой остановки fail-closed при недоступности модели. Распознавание ненадёжно и Windows-реализация не проверена; уже выполненные действия не отменяются.

- Голосовой вызов «Джарвис» (`WakeWordSession`, `WakeWordPhrase`, `MainWindow.WakeWord.cs`) включается только явно, слушает микрофон до отключения и может ошибаться. После срабатывания 15-секундная запись отправляется в Groq; текст подтверждается один раз, авторежим затем выполняет действия с паузой. Вызов приостанавливается на время задачи и возобновляется после неё; при выходе/смене модели выключается. Требуются локальная модель Vosk и DLL из комплекта, микрофон, разрешения; реальные Windows/Groq не тестировались.

- Вызов и голосовой стоп переведены на локальную модель Vosk, которая находится в `VoiceModel` рядом с DesktopPet.exe; нужны и внешние нативные DLL из Vosk 0.3.38. Русский SAPI больше не нужен для этих двух режимов, быстрые команды также используют Vosk. EXE-хеш не покрывает внешние DLL/модель. Распознаны синтетические фразы на Linux; Windows и настоящий микрофон не проверены.

- Быстрые голосовые команды также переведены с SAPI на локальную модель Vosk. Все три локальных голосовых режима используют папку VoiceModel и DLL комплекта; оригинальные голосовые запросы задач по-прежнему отправляются Groq.

- В «Расширенных» доступны сторонние explorer.bat и win-tweaker.bat из пользовательского архива: только явный запуск по кнопке с предупреждением; не выполняй их при тестах. Встроенные файлы не меняются, закреплён SHA-256 и сохраняется блокировка от изменения на время запуска. Win Tweaker может удалять приложения и отключать UAC и SmartScreen; полного отката нет. Права и условия распространения авторских файлов следует отдельно проверить.

- Экспериментальные проверки в `SystemInsights.cs`: физические диски через Windows Storage и Secure Boot/TPM через PowerShell. Команды постоянные, не принимают пользовательский текст и не изменяют настройки; значения могут отсутствовать или быть неточными. `LocalBenchmark.cs` измеряет только однопоточный SHA-256, сохраняет до 100 локальных результатов и не претендует на оценку всего ПК или онлайн-рейтинг. Для всех трёх проверок нужна ручная проверка на реальном Windows, для дисков — на разном оборудовании. Тест форматирования и истории — `tests/SystemInsightsTests`.

- Экспериментальный диспетчер процессов `ProcessManager.cs` / `MainWindow.Processes.cs`: действия только после выбора и подтверждения, перепроверка PID, времени запуска, пути и сеанса, запрет для своего процесса и процессов из папки Windows. Это не полная защита системных процессов; завершение может привести к потере данных. Допустимы только три обычных приоритета. `ProcessProfiles.cs` хранит ручные профили по пути EXE и не применяет их автоматически. Тесты политик — `tests/ProcessManagerTests`; необходима ручная Windows-проверка.

- Экспериментальный `PackageCatalog.cs` использует установленный WinGet с аргументами без оболочки, только источники winget/msstore и точный проверенный ID при установке или удалении. Пользователь явно подтверждает принятие условий источников и действия; условия пакета автоматически не принимаются. Исполнители сторонних программ могут менять файлы и настройки. `ResidualSearch.cs` только ищет совпадения имён папок на верхнем уровне в Program Files и AppData текущего пользователя, не доказывает принадлежность и ничего не удаляет. `tests/PackageCatalogTests` проверяет валидацию и поиск; нужны реальные испытания WinGet на Windows.

- Экспериментальный список `GameLibrary.cs` / `MainWindow.Games.cs` хранит выбранные вручную EXE отдельно в `games.json`, не запускает игры и не меняет их файлы. Кнопка защиты добавляет путь в `GameGuard` по подтверждению, удаление из списка защиту не убирает. Профили процессов открываются отдельно; игровых конфигов и автодетекта игр нет. `GameLibraryTests` проверяет сохранение и повреждённый файл; интерфейс не проверен на Windows.

- Экспериментальная запись `GameCapture.cs` / `MainWindow.GameCapture.cs` запускает только выбранный пользователем standalone PresentMon 2.6.0 x64 после проверки SHA-256 официального GitHub-актива и удерживает проверенный дескриптор до завершения. Программа отдельно не скачивается и не встраивается. PID/время/путь выбранного процесса перепроверяются; запись ограничена 5–120 сек., задержка 0–30 сек., CSV хранится локально. Расчёт интервалов Present для самой активной swap chain не равен гарантированно отображённым кадрам. `GameCaptureTests` проверяет CSV и границы аргументов; тест с реальной игрой, античитом и Windows не выполнялся.

- Экспериментальный `ProcessAffinity.cs` / `MainWindow.ProcessAffinity.cs` позволяет явно изменить маску только выбранного процесса с повторной проверкой личности и действующими ограничениями `ProcessManager`. Исходная маска записывается до изменения и может восстанавливаться только для того же PID/времени запуска/пути. Несколько групп CPU не поддерживаются. Это не эксклюзивное резервирование ядер и не настройка прерываний. `ProcessAffinityTests` проверяет валидацию и сохранение резервов; изменения маски на Windows необходимо проверить вручную.

- В тестовой ветке редизайна раздел «Расширенные» начинаетcя с адаптивного каталога инструментов: четыре группы, строки с назначением и прежними подтверждениями. Код — `wpf/MainWindow.ToolDashboard.cs`, Windows smoke-проверка — `tests/SmokeToolsDashboard.ps1`. Визуальный вид и масштабирование требуют ручной проверки на Windows; тестовая сборка не является релизом.
